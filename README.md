На 4 балла:

## Запуск контейнера.

Сборка образа:
```bash
docker build -t counter-app .
```

Запуск нашего контейнера:
```bash
docker run -d --rm --name counter -p 8080:8000 -e GREETING="Привет из Docker" counter-app
```

## Отчет о проверках. 

Статус контейнера:
```bash
docker ps --filter name=counter
```
GET до инкремента:
```bash
curl -fsS http://127.0.0.1:8080/
 # Ожидается: "count": 0
```
Инкремент:
```bash
curl -fsS -X POST http://127.0.0.1:8080/increment
```
GET после инкремента:
```bash
curl -fsS http://127.0.0.1:8080/
 # Ожидается: "count": 1
```

С полным списком проверок уровня на 4 балла можно ознакомиться в файле `logs-4.txt`.








На 6 баллов:


## Запуск.

cp .env.example .env
docker compose up -d

## Переменные окружения.

Значения берутся из `.env` (шаблон — `.env.example`):

- `PORT` — порт на хосте, по умолчанию 8080, но значение можно менять;
- `GREETING` — текст приветствия, по умолчанию «Привет из Docker», текст опять же можно менять.

## Проверка сохранения данных (Через именованный volume, называемый countdata)

curl -fsS http://127.0.0.1:8080/        # запомнить count
docker compose down
docker compose up -d
curl -fsS http://127.0.0.1:8080/        # count не сбросился — данные сохранились

## Отчёт о проверках

Запуск через Compose: `docker compose up -d`, сервис отвечает на настроенном порту.

Настраиваемый порт: PORT=9090 в `.env`, `docker compose up -d --force-recreate`, 
сервис отвечает на 9090. Таким образом, порт можно менять.

Настраиваемое приветствие: GREETING=«Привет, проверка!» в `.env`, после пересоздания приложение отвечает новым текстом.
Дефолт возвращён обратно.

Проверка, что сервис живой: `curl -fsS http://127.0.0.1:9090/healthz` → `{"status": "alive"}`.
Сервис корректно возвращает health-статус на настроенном порту.

Сохранение данных: после `docker compose down` и повторного `up` счётчик сохранил свое значение из предыдущего запуска (count: 2), 
hostname контейнера при этом сменился — данные лежат в именованном volume `countdata`, а не внутри самого контейнера.

`.env` добавлен в `.gitignore`, в рабочем репозитории только `.env.example`.
